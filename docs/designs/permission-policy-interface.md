# 工具权限显式接口计划

状态：已在 PR #36 实施。原问题核对基线：`76e0213`。本计划保留现有权限决策语义，集中表达 Harness 的调用位置。

目标是让一条工具调用的预检、扩展处理、执行前复核及拒绝路径能沿显式接口追踪。现有两道检查已经会在异常时阻止执行；这项修改属于可审查性与维护性重构，不以“当前异常会放行”为前提。

## 当前边界

[`permission.setup()`](../../src/virgo/features/permission.py) 将预检以优先级 100 注册到 `tool_call`，同时把对象放入 `services["permissions"]`。[`AgentSession._before_tool_execute()`](../../src/virgo/harness/session.py) 则直接从该字典查找对象，再调用执行前复核。

预检自身捕获异常并返回 `Block`；执行前复核的异常由 [`agent/loop.py`](../../src/virgo/agent/loop.py) 转成错误结果。快照已经覆盖模式、参数、规则、审查上下文和相关路径，复核还会检查路径边界。以上能力全部保留。

## 显式接口

在 Harness 层定义小型权限契约，至少包含 `preflight(event)` 和 `before_execute(event)`，返回 `Block | None`。内置 `Permissions` 实现该契约，Harness 在两个检查点调用同一个已绑定实例。

使用明确的注册入口绑定策略，消除执行路径中临时查找 `services` 的操作。`services["permissions"]` 保留为同一对象的兼容读取入口，供权限命令、队友模式和现有扩展使用；不能复制出第二份审批缓存或各 Agent 的权限模式状态。

通过现有配置明确禁用 permission 功能时，绑定明确的无检查策略，保持既有行为。配置要求启用、但策略未成功注册时，应报告初始化错误，不把异常缺失当成用户主动禁用。直接替换 `services["permissions"]` 不再作为替换策略的隐式入口；需要自定义策略的扩展改用显式注册入口，并在迁移说明中记录这项变化。

权限对象内部继续管理快照、审查、批准缓存、拒绝记录和审计。Harness 只负责调用顺序、异常转成阻止结果，以及选择已绑定的策略，不复制权限判断。

## 两个检查时点

预检仍在参数准备和 schema 校验后，以工具调用的源顺序执行。允许进入执行阶段后，工具循环仍在每个工具实际执行前调用复核，位置保留在线程池任务或串行任务内部。

不能把复核提前到整批预检结束时：前面的工具、扩展或人工审批可能在后面的工具启动前改变模式、参数或路径。检查与执行之间也不扩展为文件系统沙箱或彻底消除路径竞争的承诺。

预检或复核返回拒绝、抛出异常、审查被取消时，工具函数都不得被调用。普通扩展异常仍按现有 EventBus 规则提示并隔离；安全检查不再依赖这一通用异常策略。

## 钩子顺序兼容

当前 `EventBus.on()` 接受任意整数优先级，按优先级降序、同优先级按注册顺序执行。默认顺序是权限 100、命令钩子 50、普通扩展 0，但扩展可以注册 200 或 100。直接把权限预检固定移到所有扩展之前会改变行为。

本次选择保留现有顺序，由 Harness 显式组织兼容阶段：

1. 获取本次 `tool_call` 的有序处理器快照，运行原先排在权限注册位置之前的扩展；若返回 `Block`，仍立即结束。
2. 显式调用已绑定策略的 `preflight()`；拒绝或异常时结束。
3. 继续运行原先排在权限位置之后的处理器，包括命令钩子和普通扩展，保留各自的优先级、注册顺序和首个非空结果短路行为。
4. 每个工具实际执行前，显式调用同一策略的 `before_execute()`。

权限从普通回调改为显式阶段；原来的优先级和注册序号只作为扩展兼容边界。EventBus 提供供 Harness 调用的边界令牌和处理器快照接口，Harness 不直接修改 `_handlers`。权限禁用时不插入检查阶段，扩展顺序仍然相同。原权限回调注册必须移除，避免重复审批和重复审计。

保留单次派发的快照语义：处理器在派发期间增加或移除其他处理器，只影响下一次调用。用户扩展仍可改写参数或拒绝调用；参数变化由执行前复核重新检查。

这是明确的兼容取舍：首版不承诺权限一定早于高优先级用户代码。以后若要把所有扩展统一移到权限之后，应单独做有迁移说明的行为变更。

## 实现落点

| 位置 | 修改内容 |
| --- | --- |
| `harness/session.py` 与必要的小型契约模块 | 策略绑定、显式预检、显式复核、注册失败处理 |
| `harness/extensions.py` | 有序快照、权限位置兼容边界、扩展策略注册入口 |
| `features/permission.py` | 实现契约，删除普通 `tool_call` 注册，保留模式和审计逻辑 |
| `agent/types.py`、`agent/loop.py` | 保留两个现有回调入口与执行时点，避免扩大 Agent 对 Harness 的依赖 |
| `docs/ARCHITECTURE.md`、`docs/EXTENSION_MIGRATION.md` | 写明显式阶段、任意优先级的实际顺序、自定义策略迁移方式 |

优先复用当前的 `ToolCallEvent`、`Block` 和 `AgentConfig`，不引入通用策略框架。工具结果钩子、输出预算、shell 命令钩子的载荷与工作目录均保持现有行为。

## 实施顺序与验收

1. 先运行现有权限与真实 Session 场景，列出尚未覆盖的顺序和异常组合。已有测试能覆盖的行为不另写测试。
2. 对任意优先级、同优先级、动态注册快照和显式策略失败等必要缺口，先补真实 Session 驱动的端到端回归，再修改实现；不在实现后补测试。
3. 引入策略契约和绑定入口，接执行前复核，再迁移预检并删除旧注册。迁移中不得暂时失去任何一道检查。
4. 核对主 Agent、子 Agent、队友使用同一条 Harness 路径；更新迁移文档并运行相关场景。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 默认工具调用 | 权限预检、命令钩子、普通扩展、执行前复核、工具执行顺序不变 |
| 优先级 200、100、50、0 及同优先级扩展 | 顺序与重构前一致；被提前拒绝的调用不新增审批 |
| 扩展修改参数、切换 plan、改变符号链接 | 实际执行前重新检查，不能沿用旧批准 |
| 批量工具全部预检通过后发生模式变化 | 后续尚未执行的工具仍被阻止 |
| 预检或复核抛出异常，人工审批期间取消 | 工具没有副作用，模型和 UI 收到错误结果 |
| 自动审查失败、拒绝、人工批准和会话批准 | 保持现有决策、审计和缓存范围，不新增重复审批 |
| 权限功能显式关闭或注册缺失 | 前者保持配置语义；后者明确失败，不静默放行 |
| 子 Agent、队友及会话切换后迟到的请求 | 使用原绑定的审查来源、取消信号和审计存储 |

验证入口优先使用已有 `tests/harness/test_session.py`、`tests/features/test_permission*.py`、子 Agent 和队友场景。

## 交付范围

原计划的独立交付标题（现按用户要求合并在 PR #36 实施）：`refactor: make tool permission checks explicit in the harness`。

不修改权限规则语法、模式含义、自动审查模型策略或 JSONL 审计格式。若与保存失败修复衔接，保存故障仍由会话持久化状态阻止调度，不能因权限重构将其降级成普通扩展异常。

## 实现说明

契约位于 `harness/permissions.py`。内置策略通过 `register_permission_policy()` 注册，禁用时使用 `NoPermissions`。`EventBus.boundary()` 预留原优先级位置，Harness 对一次快照分段派发；检查异常直接变为 `Block`。单个工具事件记录预检时的策略，使执行前复核使用同一实例。迁移示例见 [扩展迁移](../EXTENSION_MIGRATION.md#持久化故障权限策略与-runtime-构造)。
