# 会话保存失败处理计划

状态：已在 PR #36 实施。原问题核对基线：`76e0213`。本计划只处理会话持久化失败，不依赖另外两项 Harness 重构。

目标是让保存失败立即可见，并停止继续产生无法可靠保存的工作。保留已经生成的消息和工具结果，维持消息与记录 ID 的对应关系，继续使用现有 JSONL 格式。首版采用失败后暂停的策略，不自动降级为正常的内存会话。

## 问题与依据

[`SessionStore.append()`](../../src/virgo/harness/store.py) 先更新 `entries`、`by_id` 和 `leaf`，再调用 `_write()`。写入失败后，[`Runtime._on_event()`](../../src/virgo/harness/session.py) 会跳过后续 ID 更新、扩展事件和 UI 事件；[`Agent._emit()`](../../src/virgo/agent/agent.py) 随后吞掉监听器异常。

离线复现中，一次用户消息写入失败、后续写入恢复后，Agent 仍执行工具并回答。内存有 4 条消息，磁盘有 3 条，`Runtime.ids` 有 3 项；文件出现缺失的父节点引用，UI 没收到该消息的结束事件，也没有警告。持续写入失败可能另外触发权限审计失败并阻止工具执行，不能据此认为所有失败都会继续执行工具。

## 设计决定

### 存储保留逻辑历史并记录失败状态

保留内存中的逻辑记录，增加独立的持久化状态，区分正常保存、主动使用内存存储和保存失败。第一次失败记录目标路径、异常、失败记录 ID，以及最后确认写入成功的位置；后续收尾事件仍可进入逻辑历史，但不再尝试向故障文件追加。

`append()` 不把失败伪装成成功。使用明确的保存异常携带本次已分配的记录 ID，使 Runtime 能完成消息与 ID 的关联；其他调用方仍能识别失败。标记持久化状态必须先于异常向上传播，避免异常被某个扩展或监听器捕获后丢失故障状态。

不要仅通过回滚 `SessionStore.entries` 处理错误：Agent 消息可能已经进入内存，工具也可能已经产生外部效果。存储和 Runtime 必须共同定义“内存保留、磁盘未确认”的状态。

### 写入失败后暂停后续调度

Harness 按 Runtime 绑定的会话归属接收故障通知。通知在释放存储锁后处理，不能持有存储锁调用 UI、权限审查或等待 Agent，避免锁顺序问题。

主会话存储失败时，停止依赖该存储的主 Agent、子 Agent 和队友的后续调度。队友自己的记录文件失败时，至少停止该队友并通知所属会话。其他独立会话继续运行。

检查点覆盖下一次模型请求、工具预检、每个工具实际执行前，以及 `prompt`、`run_pending`、steering 和 follow-up 的重新启动。故障状态不能仅依赖取消信号，因为 `Agent.prompt()` 会清除自身拥有的信号。已启动的工具使用现有协作取消机制；已完成的外部效果不回滚，结果继续交付并标记未保存。

尚未消费的用户输入和排队通知保留在原会话，显示为未处理；不能因运行提前退出而丢失，也不能由唤醒循环反复尝试执行。

### 事件完成与保存结果分别处理

调整 `Runtime._on_event()`，使保存异常不会跳过消息 ID、必要的内存状态、扩展通知和 UI 通知。每条已经进入 `Runtime.messages` 的消息都必须有对应的 `ids` 槽位；不得在后续成功保存时造成位置错配。工具结束和 Agent 结束事件仍需送达，避免界面一直显示运行中。

只在持久化边界捕获明确的保存错误。普通用户监听器仍保持故障隔离，不把 `Agent._emit()` 改成任意监听器异常都终止运行。

直接写存储的路径也必须进入同一故障处理，包括权限审计、模型用量、压缩记录、模型切换及扩展自定义记录。UI 提示不得通过再次写入同一个故障 store 实现。

### JSONL 与恢复边界

先完成记录序列化，再尝试文件写入；只有文件上下文正常退出后，才更新“本次写入成功”和 `_header_written` 状态。关闭或缓冲刷新失败也按保存失败处理。成功返回不扩大为掉电后必然持久化的承诺，首版不引入每条记录 `fsync`。

第一次失败后禁止继续追加，防止在半行或缺失记录后继续扩大损坏。保留原文件和进程内逻辑历史，不自动截断、覆盖、重试，也不宣称磁盘已恢复一致。自动断尾修复、原文件重试和另存恢复不纳入此 PR。

用户仍可查看当前内容、切换到其他可用会话或新建会话。故障会话不得因一次新 prompt 自动恢复，界面必须说明未保存内容仅保留在当前进程，退出后无法保证恢复。重新加载磁盘只代表恢复已有磁盘记录，不能清除原运行实例的未保存提示或替换其内存内容。

JSONL 的版本、header、记录类型及父子关系表达保持兼容。故障状态保存在运行时，不要求旧文件迁移；`path=None` 的正常内存会话和移入回收站后停止写入的行为不视为磁盘错误。

## UI 与实现落点

| 位置 | 修改内容 |
| --- | --- |
| `harness/store.py` | 保存状态、明确的保存异常、写入完成时点、故障后的追加约束 |
| `harness/session.py` | 消息与 ID 一致性、故障归属、停止调度、继续交付收尾事件 |
| `agent/loop.py` | 必要时补充模型调用前取消检查，特别是用户消息保存失败后尚未发起请求的路径 |
| `harness/ui.py`、CLI 与 TUI | 显示目标会话、失败原因和未保存状态；隐藏会话切回后仍可见 |
| `harness/compaction.py`、`telemetry.py`、权限及其他写入方 | 核对异常不会被转换成成功、错误重试或会话继续运行 |

首次故障显示一条明确错误，随后保持状态提示，不因每条收尾记录重复刷屏。plain 和 print 模式向 stderr 输出；JSON 模式提供可识别的保存失败状态，并在非交互任务结束时返回失败退出码，不能只输出一个看似正常的最终答案。自定义 UI 的兼容回退使用现有 `print(..., "error")`。

## 实施顺序与验收

1. 先列出故障场景，并在已有真实 Session、离线 provider 和 TUI 流程中补足必要的端到端回归；这些场景涉及历史丢失和静默执行，属于必须验证的行为。测试在对应实现之前写，不在实现后补测试，不增加只镜像内部字段的单元测试。
2. 实现 Store 的失败状态与写入语义，再接 Runtime 的消息记账和停止调度。
3. 接入所有直接写入方，完成 UI、非交互退出及故障会话保留行为。
4. 更新架构和测试文档，运行受影响的现有端到端场景及新增故障场景。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 首次打开、目录创建、序列化、写入、关闭失败 | 错误可见；不假装保存成功；后续模型和工具不再启动 |
| 一次消息保存失败后文件系统恢复 | 不自动续写；消息和 ID 不错位；保留故障状态 |
| 写入部分字节后失败 | 文件不被继续追加或自动覆盖；未保存内容仍可查看 |
| 工具已完成后保存结果失败 | 工具结果与结束事件可见；后续任务停止；不声称撤销工具效果 |
| 权限审计或后台子任务记账失败 | 原所属会话收到通知；权限不被放行；不误报到新会话 |
| 隐藏会话失败、切换、新 prompt、排队通知 | 原会话状态持续可见；不能重新启动故障运行；其他会话可用 |
| 无故障及正常内存会话 | 事件顺序、JSONL 重载、分支和回收站行为保持现状 |

实现 PR 以真实用户可观察的行为作为验收依据；必要的故障注入只替换文件 I/O 边界，不替换整个 Session 或 Agent 循环。

## 交付范围

原计划的独立交付标题（现按用户要求合并在 PR #36 实施）：`fix: surface session persistence failures and stop affected runs`。

完成条件是保存失败可见、后续工作停止、内存历史与 ID 仍一致、旧 JSONL 可读，且不会静默恢复写入。PR #36 同时包含权限接口和 Runtime 创建入口，持久化故障仍由独立状态控制。

## 实现说明

`SessionSaveError.entry` 携带已经进入逻辑历史的记录，`save_error` 保存首次失败，`last_saved_id` 标记最后确认完成的记录。写入期间只设置取消信号；释放存储锁后通知 UI，分支审计写入也遵循同样规则。Runtime 继续完成消息 ID 和 UI 事件；`AgentConfig.can_run` 在启动和模型请求前检查持久化状态。故障后的输入留在原会话队列，plain/TUI 调度器不反复唤醒它。JSON 输出增加 `session_save_failed`，print 模式返回非零退出码。

### 切换后的恢复

AgentSession 在切走时保留有文件路径的原 Runtime 和待处理队列，即使此时尚未失败、队列也为空。后台记账可能稍后才失败，因此不能仅凭切换时的健康状态丢弃原实例。缓存与已访问 store 一样归当前进程所有；移入回收站会移除对应缓存，空白会话不加入恢复列表。

`/sessions` 和 TUI 列表合并磁盘目录与保留实例；故障会话的标题、消息数和更新时间来自内存，即使磁盘只有合法前缀、半行或空文件。`live_store()` 供 UI 在读取磁盘之前查找已有实例，重新打开时恢复原 Runtime 和队列，并将 Runtime 模型同步到 Session 当前选择；此操作不会重试保存或解除暂停。

TUI 离开保存失败或仍有后台工作的会话时保留其面板，包括跨工作空间切换。选择已有历史优先交给所属面板；如果该面板正在运行另一会话，则提示结束或中断后再打开，不能通过创建磁盘副本绕过故障。故障状态只属于当前进程，退出后仍无自动恢复保证。
