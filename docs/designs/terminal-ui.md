# 终端 UI 优化方案

状态：设计提案，尚未实现。日期：2026-11-13。基于 80×24 的 macOS Terminal 截图与当前 Textual 实现。

推荐将定时任务改为顶部展开的独立工作页，使用“标题｜执行频率｜下次执行时间”三栏列表、轻量选中态和就近的快捷键提示。保留终端字符网格与键盘操作习惯。任务管理是首个落点，随后将同一视觉规则用于模型、会话和权限界面。

## 问题依据

1. `ConversationPane` 将通用选项列表放在底部 `#dock`；上方 `#body` 占满剩余空间。空对话打开任务列表时形成大面积空白。
2. `manage_schedules()` 把 `Schedule.describe()` 的 ID、类别、时间、标题拼成单个字符串，借用通用 `ChoiceList`。折行后字段失去对齐，标题被辅助信息挤压。
3. `#completions` 复用于任务管理，继承命令补全的 6 行高度上限、紫色边框与整行紫底白字选中态。
4. 顶部快捷键距离操作区过远；版本、路径占独立行；底部两行指标在管理任务时缺少直接用途。
5. 中文任务流程与英文操作提示混杂；任务、创建、返回共享一个选项层级。

## 推荐布局

### 任务工作页

顶部保留一行 `V_ Virgo / 定时任务` 与缩写路径。内容从顶部开始排布，页面标题仅为“定时任务”，不附加任务数量；实际调度时区独立显示。列表占用剩余可用高度，底部一行放当前页面操作。版本移入关于信息。

```text
 V_ Virgo / 定时任务                                      ~

 定时任务                                    Asia/Shanghai

   标题                          执行频率       下次执行时间
 › 每日 arXiv KV-cache 论文简报    每天 09:00     11/14 09:00

 ↑↓ 选择   Enter 详情   n 新建   Esc 返回对话
```

示意省略了空白行；日期为截图当日的演示数据，真实页面使用调度器已有的下次执行值。短标题是建议用户采用的命名示例，不代表自动删改现有标题。

- 列表固定为“标题｜执行频率｜下次执行时间”三栏，使用独立列布局和对齐的表头；每项通常占一行，不再添加编号或下次执行的辅助行。
- 执行频率列显示“每天 09:00”等完整规则摘要；下次执行时间列显示实际日期和时刻。两列预留宽度，标题使用剩余空间。
- 列表不另设编号列；详情需要展示编号时使用 1、2、3……，不显示内部 ID 前缀。
- 页面不显示运行前提类说明标注。
- 长标题按显示单元宽度截断并加省略号；详情保留完整原文。中文、组合字符及 emoji 不按 Python 字符数截断。
- 初次打开选中第一项；返回时恢复选中项和列表位置。任务删除后选中邻近项，不跳到“返回”。
- 创建入口使用 `n`，返回使用 `Esc`，不混入任务数据行。快捷键始终可见。
- `Enter` 打开详情页，展示完整标题、正文、规则、时区、下次执行与数字编号；正文滚动，操作区固定。编辑与删除在详情中提供，删除沿用二次确认。
- 空列表显示“暂无定时任务”和 `n 新建任务`；长列表滚动并显示位置，如 `3 / 18`，不增加永久侧栏。

### 备选：紧凑任务弹层

在对话上方显示宽度不超过 68 列、随内容增高的单边框弹层，集中呈现任务与操作。适合少量任务和快速跳转；数量增加或阅读长正文时，需要更多层级切换。优先选择工作页以容纳后续任务管理需求。

### 尺寸适配

- 80×24：一行品牌、一行页面标题、一行三列表头、一行一项、底部一行操作；正文充分使用剩余行数。
- 小于 64 列：保持三栏顺序与对齐，优先缩短标题；必要时允许频率、日期和时刻在各自单元格内换行，不移入额外的辅助信息行。
- 宽屏仍为单列，内容最大宽度建议 100 列，避免焦点横跨整个超宽终端。
- 低于 18 行：压缩区块留白，保留三列表头和底部操作提示，选中项跟随滚动。

## 视觉与交互规则

- 正文使用终端默认前景和背景。紫色集中用于 `V_`、选中箭头和关键焦点；普通分隔线使用中性色。
- 选中行用 `›` 加轻量背景或反色表达，不依赖颜色单独传意。终端背景未知或仅支持有限颜色时，优先箭头加反色，不硬编码浅色底。
- 深浅主题分别提供强调色与次级文字色；避免将所有辅助信息直接设为 `dim`，在白底实机核验可读性。
- 页面只保留必要的水平分隔线；详情和正文不层层套框。不引入阴影、渐变、大图标或无法用字符网格表达的装饰。
- 左右留 1–2 列；区块间隔 1 行。TUI 文字使用终端统一字号，层级由位置、留白和字重表达。
- 同一流程的操作文案使用中文；模型 ID、技术标识保持原文。
- 任务页隐藏模型用量和 cache 指标。对话页合并为一行状态：权限模式、模型/推理强度、必要的上下文占用；输入输出及缓存明细按需查看。危险权限模式仍显著显示。
- 创建流程沿用标题、正文、时间、确认顺序，增加步骤标记；字段错误紧邻字段，返回编辑保留草稿。保存后返回列表并选中新增任务。
- `Esc` 在详情返回列表，在列表返回对话；编辑中的未保存内容须明确处理。`n` 等单字母快捷键仅在列表页面生效，不能截获正文输入。

## 实施顺序

### 第一阶段：定时任务页面

新增专用任务页面与结构化列表项，使管理页面脱离 `#completions`。调整 `schedule_commands.py` 与 UI/bridge 接口，以稳定任务 ID 返回选择结果，而非通过显示文本查找。数字展示编号与内部任务 ID 显式映射，避免删除或刷新列表后误操作其他任务。保留普通终端的文字流程。现有标题、正文、任务数据与调度语义保持兼容。

### 第二阶段：公共视觉规则

在 `cli/tui/app.py` 和组件中集中管理颜色、边距、焦点及状态栏规则，移除散落的紫色边框和白色文字常量。命令补全仍靠近输入框；管理页面使用独立布局。再应用于模型、会话和权限界面。

### 验收场景

本提案不修改运行代码，也不新增测试。后续实现优先复用真实终端端到端验证：

- 浅色和深色终端下的 80×24、60×18、120×40 布局。
- 空列表、单个长中文标题、多于一屏的任务、组合字符与 emoji。
- 列表进入详情再返回、编辑取消、创建成功、删除当前项后的焦点位置。
- 滚动长正文、切换会话、窗口缩放，确认内容和草稿未丢失。
- 普通终端降级流程可用，调度时区与运行时语义未变化。

浏览器预览只用于讨论布局和信息层级；实际颜色映射、字符宽度及行高以终端验收为准。
