Eleven Windows test-assumption failures were fixed. Seven application cases

Main `811bc024340dbe2dd496a909b9c665ee05bd1150` includes PR #9 and subsequent shell
selection/runtime changes. Its [Shell selection E2E run](https://github.com/0xAstraZhang/Virgo/actions/runs/43156363485)
passed, but runs only `tests/harness/test_shell_commands.py` and
`tests/tools/test_shell_runtime.py`, not the complete suite or the seven cases above.
Source review and local reproduction found:

- The selected-shell path recognizes `.exe` and passes `-e -o pipefail` for Bash.
  Background jobs now use this path. The old five-failure count cannot simply be
  carried forward to this implementation.
- The compatibility path in `tools/bash.py:spawn()` still compares the executable
  name against `bash`/`zsh` without stripping `.exe`. A real Bash executable invoked
  through a temporary `bash.exe` symlink on Linux returned success and ran the next
  command for both `false; printf continued` and `false | cat; printf continued`.
  Passing that executable as a probed `Shell` stopped both commands with exit 1.
  This demonstrates the remaining filename-dependent bug, not a Windows test run.
- The `date` classifier in `features/permission_scope.py` still compares native
  `Path` parents to `/bin` and `/usr/bin`. Windows path parents are `\\bin` and
  `\\usr\\bin`, so the mismatch remains; neither the classifier nor its two
  assertions changed from the failing revision.
- Main has no full-suite PR/baseline comparison workflow or `ci/compare_tests.py`.
  The shell-only workflow does not replace the CI added by PR #10.

PR #10 integrates this main revision, preserving its application/tests and both
README sections. Its comparison CLI end-to-end checks, Ruff, whitespace checks,
and 122 focused Linux Bash/permission tests passed locally. The application bugs
remain outside this CI-only PR; exact current platform totals require its new
full-suite CI run and must not be inferred from either PR #9 table.

## Environment and limits

Each pair used the same interpreter and runner family, with locked dependencies:

- Linux x86_64: Python 3.13.18, Ubuntu runner; zsh and curl installed by the workflow.
- Windows x86_64: Python 3.13.17, Windows Server 2025; native default tool shell.

These are one complete run per revision and platform, not a flaky-test stress test.
No live provider credentials were supplied. Windows POSIX PTY cases remain untested.
The Python patch versions differ across operating systems but match within every
PR/baseline pair. Future `*-latest` images and Python 3.13 patch versions may change.
