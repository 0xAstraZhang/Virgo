# 叶级功能需求

[文档中心](../README.md) · [公理设计](axiomatic-design.md) · [验收证据](functional-acceptance.md) · [English](../../en/development/functional-requirements.md)

在选定分层编程 Agent 运行时（DP0）的前提下，本目录将 FR0 分解为可观察的结果，并按 A–H 八个功能域组织。功能域是导航分组，不是八个可独立调整的 FR–DP 对，也不宣称构成已经证明的公理设计层级。叶级编号标识功能结果，而不是实现包；功能在 Core、Plugin 与 Extension 之间迁移时，其 FR 不变。主要 DP 描述设计机制或策略，必要时附实现名称以便定位。[设计分析](axiomatic-design.md)定义约束及稀疏影响矩阵，[验收映射](functional-acceptance.md)将需求关联到可执行检查。

设计选择或验收边界不同时才拆分，不必拆到每个 API 或函数。主要 DP 编号不宣称机制独立：搜索和获取共享能力规划与 Web 调用上限，任务、压缩和子任务共享模型调用上限。任意模型响应下的任务成功属于 FR0，而非编排协议保证；历史结构保留也不能证明语义记忆率。

## A — 用户交互

| 叶级 FR | 要求的结果 | 主要 DP | 验收边界 |
| --- | --- | --- | --- |
| **FR-A.1** | 在选定交互界面显示对话进展与结果 | **DP-A.1：** TUI/REPL 渲染、转录投影、事件观察 | 流式和终态结果保持正确运行归属；视图变化保留对话状态 |
| **FR-A.2** | 向非交互调用方返回可用结果 | **DP-A.2：** Print/text/JSON 输出适配器 | 输出遵守请求格式；并发 JSON 记录完整且可解析 |
| **FR-A.3** | 将命令和普通用户文本路由到对应操作 | **DP-A.3：** 命令解析、会话/运行时门面方法 | 有效命令到达处理器；转向/跟进文本不被误分类；无效命令保留当前会话 |
| **FR-A.4** | 通过显式声明能力的输入适配器收集决定 | **DP-A.4：** 显式确认/输入能力声明与适配器选择（`UI`） | 相同请求与回答在支持的适配器上保留审批结果；缺少确认能力时阻止交互提权 |
| **FR-A.5** | 按所选语言提供受支持的界面文本 | **DP-A.5：** 会话级翻译器与语言资源 | 工具/帮助/审批文本使用所选语言且占位符匹配；回答语言指引仍遵循用户请求 |
| **FR-A.6** | 请求用户决定，并区分回答、拒绝、超时与取消 | **DP-A.6：** `ask_user` 选项、交互状态与超时策略 | 回答保留用户意图；非交互模式报告未回答；取消或无人值守问题不虚构决定 |

## B — 模型交互

| 叶级 FR | 要求的结果 | 主要 DP | 验收边界 |
| --- | --- | --- | --- |
| **FR-B.1** | 获得规范化的流式文本、推理、工具调用与终态 | **DP-B.1：** 协议专用适配与流规范化（`ai/providers/*`） | 等价协议夹具产生预期消息和停止/错误分类；取消后停止消费 |
| **FR-B.2** | 使用指定账号，不借用其他提供商的凭据 | **DP-B.2：** 凭据查找、OAuth/API 认证、端点绑定 | 账号/端点选择使用匹配凭据；被拒凭据不静默切换到另一个身份 |
| **FR-B.3** | 选择可用模型及其支持的推理强度 | **DP-B.3：** 目录发现/缓存、模型选择与支持的强度映射（`ModelRegistry`） | 选定模型/强度进入请求；失败的选择保留当前配置 |
| **FR-B.4** | 以运行时可处理的形式表达模型失败 | **DP-B.4：** 提供商错误分类与规范化诊断元数据 | 可重试、上下文超限、能力不支持、致命失败与取消保留各自含义 |

## C — 操作与信息获取

| 叶级 FR | 要求的结果 | 主要 DP | 验收边界 |
| --- | --- | --- | --- |
| **FR-C.1** | 读取和定位目标文件内容 | **DP-C.1：** Broker 读取/检索、路径作用域与匹配规则（`tools/fs.py`、`file_access.py`） | 返回目标内容或匹配结果；被拒读取和检索不暴露作用域外内容 |
| **FR-C.2** | 修改目标文件而不造成非预期变更 | **DP-C.2：** Broker 写入/编辑、路径准入、唯一匹配与原子替换（`tools/fs.py`、`file_access.py`） | 目标内容被修改；越界或歧义编辑保持文件原样 |
| **FR-C.3** | 执行命令并观察完成、失败或取消 | **DP-C.3：** Shell 选择、执行上下文、进程监管 | 结果描述实际执行；取消和清理遵守选定进程契约 |
| **FR-C.4** | 取回长输出，同时限制模型/UI 载荷大小 | **DP-C.4：** 输出字节上限、引用存储、分页/检索与保留策略（`OutputStore`） | 来源会话可读取有界引用；分页保留有效 UTF-8 和访问作用域 |
| **FR-C.5** | 调用配置的外部服务并报告连接/分派结果 | **DP-C.5：** MCP 传输、配置绑定、工具 Schema 与结果投影 | 配置的服务暴露有效工具；服务不可用不阻断无关启动；结果保留归属与输出上限 |
| **FR-C.6** | 使用可用且获准的能力搜索信息 | **DP-C.6：** 搜索能力选择、提供商/客户端规划及由能力拒绝触发的回退（`plugins/web`、`ai/web.py`、`tools/web.py`） | 搜索能力可用或明确不可用；回退不重复已开始的托管工作；适用上限保持有效 |
| **FR-C.7** | 使用可用且获准的能力获取内容 | **DP-C.7：** 内容获取能力选择、提供商/客户端规划及由能力拒绝触发的回退（`plugins/web`、`tools/web_fetch.py`） | 获取能力可用或明确不可用；回退不重复已开始的托管工作；适用上限保持有效 |

## D — 授权与信任控制

| 叶级 FR | 要求的结果 | 主要 DP | 验收边界 |
| --- | --- | --- | --- |
| **FR-D.1** | 仅允许有效策略授权的资源操作 | **DP-D.1：** 拒绝优先资源策略、有效执行模式选择与上下文绑定（`PermissionPolicy`） | 获准操作成功；被拒文件/网络操作产生显式结果且不扩大模式 |
| **FR-D.2** | 在支持主机上限制模型启动的任意命令 | **DP-D.2：** 原生 Shell 后端与进程启动策略 | 原生主机套件验证声明的文件系统/网络边界；Broker 夹具不能证明该边界 |
| **FR-D.3** | 获取并应用针对具体资源的用户授权 | **DP-D.3：** 审批/授权作用域、持久化与修订绑定 | 授权覆盖所请求操作/资源；拒绝、参数变化与无关任务不能复用授权 |
| **FR-D.4** | 按有效策略要求，对高危操作取得显式授权 | **DP-D.4：** 风险分类、策略控制的确认及单次操作作用域（`harness/high_risk.py`、`harness/execution.py`） | 拒绝阻止分派；一次同意不授权下一次操作 |
| **FR-D.5** | 在原生执行边界不可用时作出明确决定，不静默提权或不安全重放 | **DP-D.5：** 启动状态分类及显式单次 Host 回退策略（`harness/execution.py`） | 边界不可用时默认拒绝执行，除非获准适用的单次选择；会话模式不变；不重放可能已经启动的 payload |
| **FR-D.6** | 使项目控制的可执行配置遵守用户的信任选择 | **DP-D.6：** 配置过滤、项目信任与 MCP 配置指纹 | 不可信项目的 hooks、MCP 服务器、提供商、扩展及 `shell`、`search`、`fetch` 设置不能覆盖对应的用户设置或获得可执行授权 |

## E — 任务编排与控制

| 叶级 FR | 要求的结果 | 主要 DP | 验收边界 |
| --- | --- | --- | --- |
| **FR-E.1** | 协调多步模型/工具交互，将有效决策与结果传递至下一次获准请求或显式终态 | **DP-E.1：** 工具调用校验、调度、结果排序与循环终止规则（`agent/loop.py`、`Runtime`） | 无效调用返回错误且不分派；并发完成保持逻辑调用顺序；获准步骤进入下一次请求或显式终态。任意任务的成功属于 FR0 |
| **FR-E.2** | 在适当执行边界送达转向及跟进输入 | **DP-E.2：** 转向/跟进队列与投递优先级（`agent/`） | 排队的用户输入在下一个允许的边界送达，不被误分类或静默丢弃 |
| **FR-E.3** | 按运行时取消契约取消活动及排队工作 | **DP-E.3：** 取消传播、工作线程中断与清理协调（`agent/`、`ChildCancellation`） | 取消阻止后续分派，并遵守适用的工作线程/子任务生命周期；子任务取消不取消父任务 |
| **FR-E.4** | 遵守配置的模型请求及 assistant 轮次上限 | **DP-E.4：** 共享请求预算的作用域与原子计数、运行时轮次限制（`RequestBudget`、Agent 循环） | 上限耗尽阻止后续工作；任务、辅助调用与子任务请求共享配置的调用上限 |
| **FR-E.5** | 仅按声明的恢复条件重试或切换模型 | **DP-E.5：** 按失败分类确定的重试次数/等待预算、备用模型与 Core 重放限制（`Runtime`） | 可重试失败遵守上限；可能已经开始的宿主执行阻止不安全自动重放 |
| **FR-E.6** | 用独立对话和显式继承的上限执行、复用子任务 | **DP-E.6：** 子对话隔离、角色/工具选择、状态复用与继承限制（`SubagentStore`、子运行时） | 子历史隔离，可复用状态支持恢复，继承的权限/预算/取消限制保持有效 |
| **FR-E.7** | 在正确对话中查询、取消和收集异步工作 | **DP-E.7：** 任务生命周期、取消/结果访问及按来源路由通知（`JobManager`） | 任务到达终态；结果查询遵守归属；完成通知送达来源会话 |
| **FR-E.8** | 跨对话边界维护准确的任务清单 | **DP-E.8：** 清单校验、成功结果日志与压缩周期投影（Todo） | 有效更新替换清单；无效更新保持原样；未完成项跨压缩/恢复保留。清单不调度执行 |

## F — 会话与上下文管理

| 叶级 FR | 要求的结果 | 主要 DP | 验收边界 |
| --- | --- | --- | --- |
| **FR-F.1** | 恢复保存的对话历史与分支，不静默丢失内容 | **DP-F.1：** 带锁的追加式 JSONL 分支日志、提交与断尾修复规则（`SessionStore`） | 恢复当前分支；断尾修复保留有效记录；权威存储写入失败阻止继续执行并保留未保存历史 |
| **FR-F.2** | 将异步工作和证据归属到来源对话 | **DP-F.2：** 任务启动时的身份与分支捕获、来源传播与路由（`ExecutionOrigin`、`BranchSource`） | 切换可见会话不会将子任务结果、权限或证据转移给其他所有者 |
| **FR-F.3** | 向模型提供适用指令及当前工具/上下文契约 | **DP-F.3：** 按角色组装提示词、项目指令选择与请求预处理 | 按角色选择的指令进入请求；普通轮次保持追加式前缀；权限变化更新适用边界 |
| **FR-F.4** | 在模型上下文限制内持续使用长对话 | **DP-F.4：** 触发/目标预算、尾部选择、剪枝与可移植摘要策略（`CompactionController`） | 工具对与保留尾部保持有效；成功检查点可恢复；取消/失败不以不完整摘要替换历史。事实保留与任务质量需另行模型评测 |
| **FR-F.5** | 发现并应用指定技能指令 | **DP-F.5：** 技能发现、优先级与显式调用 | 选中指令进入请求，不读取任务允许范围外的资源 |

## G — 可观测性与诊断

| 叶级 FR | 要求的结果 | 主要 DP | 验收边界 |
| --- | --- | --- | --- |
| **FR-G.1** | 追溯已记录模型请求的有效配置 | **DP-G.1：** 分派前请求头及辅助请求元数据（`Runtime`、`harness/telemetry.py`） | 请求头及辅助记录反映有效模型、协议、推理强度及适用输出上限 |
| **FR-G.2** | 在正确核算范围内汇总提供商报告的用量 | **DP-G.2：** 逐请求用量记录、归属与分支汇总（`harness/telemetry.py`、`SessionStore`） | 重试/辅助/子任务用量在相应作用域计入一次；这不等于账单对账 |
| **FR-G.3** | 捕获有用的失败身份和原因，同时限制私有数据 | **DP-G.3：** 捕获、脱敏、字段允许列表、大小上限 | 保留错误 ID/原因；凭据和排除的载荷不进入投影证据 |
| **FR-G.4** | 独立于会话持久化保留可查询诊断 | **DP-G.4：** 诊断数据库、去重、应急报告 | 已保存记录可查询；诊断写入/报告失败经兜底路径保留原故障，不损坏会话历史 |
| **FR-G.5** | 经可用查询工具只读取当前运行时获准的证据 | **DP-G.5：** 运行时作用域授权、分页与已声明查询能力选择（`DiagnosticAccess`） | 外部错误 ID 仍不可访问；新查询引用使用运行时工具快照中已声明的工具；缺少能力时不虚构工具。此保证不涵盖任意后续请求修改 |
| **FR-G.6** | 在既有请求边界和压缩之后提供相关证据 | **DP-G.6：** 待投递证据、检查点投影、投递时机 | 证据到达所属运行时；单独报告故障不触发额外模型轮次；检查点保留可用查询引用 |

| 叶级 FR | 要求的结果 | 主要 DP | 验收边界 |
| --- | --- | --- | --- |
| **FR-H.1** | 增加配置的工具和事件行为，隔离加载失败 | **DP-H.1：** 注册归属、优先级与 setup 回滚机制（`ExtensionAPI`） | setup 失败撤回所属注册；其他能力与核心启动仍可用。不宣称所有运行时回调均已隔离 |

## 使用目录

提出功能影响结论时，应说明叶级 FR、调整的 DP、固定条件与可观察的验收结果。单个夹具的测试只证明该限定场景，不证明对所有 DP 独立。共享预算仍是多个功能共同受限的显式资源约束；本目录不会为了消去矩阵元素而给各功能另设预算。

[功能验收](functional-acceptance.md)列出代表性测试、实际受控变化及结论的适用边界。
