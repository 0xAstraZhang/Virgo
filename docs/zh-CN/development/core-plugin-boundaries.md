# Core 与插件的职责边界

[架构](architecture.md) · [扩展](extensions.md) · [迁移](../guides/migrating-to-core-plugins.md) · [English](../../en/development/core-plugin-boundaries.md)

## 决策

Virgo 是围绕编程工作的 Harness。Core 负责可靠地运行模型—工具循环；可选能力通过同一套 `setup(api)` 扩展接口接入。官方维护直接支持编程的组件，不再维护通用自动化或长期 Agent 组织平台。

本决策以 `main@47e1757bda5c5cfafb3a5a508a1a6ec4d629bfaf` 为实施基线。实现复用现有事件总线、Runtime 和 `AgentSession`，不增加另一套 Agent Loop、依赖求解器、插件市场、热更新系统或 Python 沙箱。

## 职责归属

| 层级 | 负责 | 不应依赖 |
| --- | --- | --- |
| AI／模型适配器 | 原生请求与响应协议、认证、推理、厂商上下文和托管能力 | 具体能力插件实现 |
| Agent／工具运行时 | 消息顺序、流式事件、参数校验、工具批次、取消和受限输出 | CLI、TUI 或具体插件 |
| Harness Core | 会话存储、运行时身份、上下文与压缩、必要权限门、诊断证据、插件装载与注册 | 已禁用插件的实现模块 |
| 基础编程工具 | `read`、`write`、`edit`、`glob`、`grep` 和所选 Shell | 任务图、团队或工作流平台 |
| 官方插件 | 聚焦的可选工具、命令、提示章节和事件处理器 | Session 私有注册表或当前选中的 TUI 面板 |
| Host | CLI、无界面输出、Textual 展示与交互 | 强制统一的 `setup(api)` 生命周期 |

模型适配器、Host 和能力插件的生命周期不同，无需强行共用一个插件接口。保留厂商原生上下文语义，不将所有模型压缩到最低公分母协议。本次仍保留 Textual 作为 Host 依赖；是否拆包是后续决策，不以可选包数量作为完成标准。

## 官方能力

| 插件 ID | 职责 | `coding` 默认行为 |
| --- | --- | --- |
| `skills` | 技能索引与显式展开 | 启用 |
| `todo` | 当前对话的轻量清单 | 启用 |
| `ask_user` | 用户询问、取消和无人值守超时 | 启用 |
| `diagnostic_get` | 向调用方提供已授权的诊断证据 | 启用 |
| `subagent` | 独立上下文、继承限制的短期子任务 | 启用 |
| `background` | 后台任务工具、状态、取消和归属明确的通知 | 启用 |
| `web` | 搜索与读取路由、权限审查和可配置预算 | 启用 |
| `mcp` | 已配置的连接、工具和有界恢复 | 存在服务器配置时启用 |
| `auto_review` | 为 Core 权限策略提供可选的模型审查 | 启用 |

`minimal` 关闭预设中的可选能力；显式 `plugins.<id>.enabled` 覆盖预设。Git 仍通过 Shell 使用，不新增独立 Git 插件。

Core 拥有 Shell／进程执行和取消原语；background 插件复用这些原语，不复制执行器。Core 同样拥有诊断服务和面向用户的 `/diagnostics` 命令；禁用 `diagnostic_get` 只移除面向模型的证据读取工具。

## 运行时不变量

1. Core 在审批前和执行前分别检查权限，包括参数被钩子修改之后。缺失或失败的策略不能退化为全允许。禁用模型审批后，不确定操作进入人工批准路径。
2. 身份、Store、诊断授权、取消和共享请求预算跟随真实调用方。子 Agent 不能提高父运行时的权限上限；切换可见对话不会转移归属。
3. 工具和命令注册记录所属插件，名称冲突明确失败。动态替换先验证完整候选工具集，再在请求边界发布新 Schema；正在执行的批次保留自己的快照。
4. MCP 恢复先验证候选连接，失败时保留健康连接。正在执行的旧响应保留原 schema 和连接，直到批次完成；批次之外的旧句柄会被拒绝。已经无人使用的旧连接在请求、回合和结束边界回收，恢复绝不重放业务操作。即使候选连接的 schema 完全相同，也必须在请求边界发布新句柄。
5. 可选插件初始化失败会记录诊断、回滚部分注册并明确报告降级。清理回调按注册逆序运行，单个清理失败不阻断后续回调。
6. 禁用插件不导入实现、不注册工具或提示、不启动该插件的连接与后台服务。不提供运行中热卸载；新会话构造时应用配置。
7. Python 扩展是在进程内运行的可信代码。工具权限门不能限制任意 Python 操作；项目扩展的信任必须来自项目无法自行控制的位置。CLI 信任仅适用于初始工作区；切换历史会话或新开 TUI 面板时，若目标属于另一工作区，都必须重置该信任。

## 退役子系统依赖清单

清单在生产代码改动前完成。删除对象是仓库实现和入口，绝不自动删除用户数据。

| 子系统 | 移除的依赖 | 原样保留的历史数据 |
| --- | --- | --- |
| Schedule | Feature／命令、进程级工作区归属协调、轮询线程、工具、TUI 工作页和专用 UI 方法 | `<项目>/.virgo/schedules.json` |
| Workflow | 脚本装载、Agent 编排、日志与重放引擎、命令／工具、随仓库示例 | `<用户>/workflows/*.py`、`<项目>/.virgo/workflows/*.py`、`<项目>/.virgo/runs/*.jsonl` |
| Team | 长期工作线程、收件箱与广播、计划审批、认领释放和 worktree 创建 | `<项目>/.virgo/worktrees/`；`<会话目录>/<lead-id>-team/*.jsonl` |
| Tasks | 跨会话任务图、归属与依赖、锁、工具和命令 | `<项目>/.virgo/tasks/*.json` 及锁文件 |
| Memory | 索引／工具、模型整理、退出时提取和提示章节 | `<用户>/memory/`、`<项目>/.virgo/memory/`，包括 `MEMORY.md` |
| Goal | 停止时续跑／评估器和命令 | 会话 JSONL 中 kind 为 `goal` 的 `custom` 条目及辅助调用记录 |

既有消息和工具结果是数据，不会因历史记录而重新注册或执行工具。工具被移除后，旧会话仍可读取。人工检查和导出方法见[迁移指南](../guides/migrating-to-core-plugins.md)。

## 验收与测量

生产改动前加入的验收位于 `tests/harness/test_core_plugins_e2e.py`。它以确定性模型驱动完整会话，覆盖文件／编辑／Shell 闭环与恢复、执行期权限、注册表发布、初始化失败与清理、项目信任、子任务限制与共享预算、历史数据和配置优先级。既有 Provider、MCP、后台任务、取消、会话和 TUI 场景继续作为回归检查。[测试退役记录](test-retirements.md)区分已取消的产品行为和仍需保留的保证。

`ci/measure_startup.py` 用临时用户目录和离线 `faux` 模型，在新进程中测量导入／构造耗时、模块／线程／工具数量，以及 Schema／系统提示字符数。在同一解释器与机器上分别使用 `--profile minimal` 和 `--profile coding`。字符数不是 Token 数；该脚本不测量编程质量、真实模型费用或成功率。

编程质量对照需要固定仓库快照、模型与推理强度、任务集、权限和预算，再记录完成情况、人工介入、工具失败、模型调用、耗时和费用。不从删除行数或离线验收推断质量提升；将实际结果及环境记录在 PR 或带日期的报告中。

带日期的[验收记录](core-plugins-validation.md)保留基线测试结果、五进程启动样本及已测证据的边界。
