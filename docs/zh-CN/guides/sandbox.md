# 原生命令沙箱

[配置参考](../reference/configuration.md) · [English](../../en/guides/sandbox.md)

## 启用与查看

原生隔离需要显式启用。默认 `disabled` 保持现有执行方式，不代表具有操作系统保护。启动时选择边界：

```bash
uv run virgo --sandbox workspace-write
uv run virgo --sandbox read-only
```

用户配置（`$VIRGO_HOME/settings.json`，默认 `~/.virgo/settings.json`）支持：

```json
{"sandbox": {"mode": "workspace-write", "network": "restricted"}}
```

项目中的 `sandbox` 配置会被忽略并提示。显式启动覆盖值优先于用户配置。未知模式、字段和网络值会导致配置失败。`/sandbox` 显示请求的模式与探测到的启动器，不改变权限，也不证明当前内核允许隔离。每次启动都会先探测实际执行边界，再启动业务命令。

## 执行边界

`workspace-write` 允许写入来源工作区，系统及解释器目录只读；`read-only` 将工作区也设为只读。每个命令有独立的可写临时目录和私有 `HOME`。输出日志始终位于来源工作区根部的 `.virgo/outputs`，从子目录运行的命令也使用此位置。宿主在记录输出前验证工作目录和输出路径，打开输出目录时不跟随符号链接，并保留该命令输出日志的精确描述符。子进程只继承 `PATH`、语言／时区／终端变量，以及私有 home/temp 路径和 `VIRGO=1`；厂商密钥及其他环境凭据不会转发。

当前唯一支持的活动网络策略是 `restricted`。Linux 使用独立网络命名空间，并用 seccomp 禁止 socket（包括按文件路径访问的 Unix socket）和 io_uring。macOS 使用默认拒绝、没有网络授权的 Seatbelt 配置。关闭隔离必须显式指定启动配置，审批结果或自动重试不能关闭沙箱。

前台 Shell、模型请求的后台命令、子运行时 Shell 共用启动器。工作区取自来源 Runtime，而不是当前可见对话或子任务更换后的工作目录。Plan 与只读子任务会把新启动命令收窄为只读。已经运行的进程保留启动时边界；模式变化不会追溯撤回其权限。

`accept-all`、allow 规则、模型审查和人工批准都不会关闭已启用的沙箱。缺少启动器／系统库、不支持的平台、命名空间拒绝或 Seatbelt 配置失败返回 `sandbox_unavailable`，不在宿主直接执行业务命令。探测成功不等于实际启动成功：实际沙箱内会运行启用隔离启动选项的固定 Python 启动程序，通过管道确认命令已完成 exec。启动失败与命令的普通非零退出分别处理，不根据 stderr 文本猜测。超时与取消保留各自状态，也不会自动重放可能已产生部分副作用的操作。Shell 结果记录实际模式与工作区，后台任务结果另外保留后端信息。

## 平台要求与限制

Linux 需要 root 所有的系统 `bwrap`（支持 `--disable-userns` 和 `--ro-bind-fd`）、系统 `libseccomp.so.2` 和创建相应命名空间的权限。受保护路径通过固定的源描述符和 bubblewrap 的 inode 校验进行只读挂载，不使用未经处理的符号链接路径作为保护挂载的来源。旧后端缺少所需选项时拒绝执行。当前 seccomp 实现支持 x86-64 与 AArch64。macOS 需要系统 `/usr/bin/sandbox-exec`。本阶段没有 Windows 原生后端：启用沙箱的请求会拒绝执行；`disabled` 保持现有 Windows 执行器。

允许读取的范围包括实际存在的系统目录（`/usr`、`/bin`、`/sbin`、`/lib`、`/lib64`、`/etc`、`/opt`；macOS 另含 `/System/Library`、`/System/Cryptexes`、`/System/Volumes/Preboot/Cryptexes/OS`、`/Library`、`/dev`、`/private/etc`）、解释器安装目录、工作区与独立临时目录，不会挂载整个宿主用户目录。位于范围外的工具、依赖缓存、证书或 SDK 可能无法使用；暂不支持额外挂载和网络例外。若工作区包含 Virgo 用户凭据／会话目录、系统／基础解释器安装目录或沙箱启动器，会拒绝执行。

支持位于工作区根部以下的活动虚拟环境，例如 `.venv`。可以使用其中已安装的命令和依赖，但 Shell 进程和 Core `write`／`edit` 工具都不能修改其解释器目录。工作区内的解释器目录别名不能是符号链接；`.venv/bin/python` 等正常的可执行文件链接仍可使用。工作区根部本身不能是解释器安装目录。

工作区根部已经存在的 `.git`、`.virgo`、`AGENTS.md` 和 `CLAUDE.md` 不允许由 Shell 写入。上述任一根部元数据路径本身为符号链接时，两个平台都会拒绝启动 Shell；这些链接不能增加宿主读取挂载，也不能替换受保护的目录项。输出目录中的符号链接同样会在记录输出前导致启动被拒绝。Linux 使用只读挂载保护已存在路径，不能阻止创建尚不存在的这些名称；macOS 也排除尚不存在的名称。Core 的 `write`／`edit` 工具另行在应用层执行工作区、只读、元数据和解释器目录限制，这些 Python 文件操作不处于 Shell 的 OS 沙箱内。

### 阻塞验收的进程生命周期限制

macOS 尚未实现完整的后代进程清理。脱离到新会话／进程组的后代进程可以在命令结束、超时或取消后继续运行，并继续进行原工作区边界允许的写入；该进程仍受原有 Seatbelt 限制。这是当前原生沙箱实现的阻塞项。清理命令进程组和私有临时目录不能证明所有后代进程已经退出。Linux 的独立 PID 命名空间通过了对应的正常退出、超时和取消验收场景。

这不是宿主 Harness、可信 Python 扩展、项目 hooks、远程 MCP 服务、厂商托管工具或可信集成直接调用底层执行函数的沙箱。可写工作区仍允许破坏普通项目文件。本阶段不提供资源配额、读取授权管理、单命令提权、Windows 隔离或运行中任务的权限撤销。

## 实现与验证

`harness/sandbox.py` 绑定会话策略和调用方，并检查文件工具上限；`tools/sandbox.py` 构造及探测原生启动边界，并检查实际命令的启动确认。现有 Shell 执行、输出记录、取消及后台任务机制管理命令进程和临时资源，但仍存在上述 macOS 后代进程限制；没有新增 Agent Loop。

`tests/harness/test_sandbox_e2e.py` 定义真实装配会话和进程的验收场景：后端不可用、配置来源、文件工具限制、间接及符号链接写入、子任务／后台归属、网络／环境隔离、已有元数据、工作区内虚拟环境、输出位置、实际启动失败、退出码、超时、取消和脱离的后代进程。原生 CI 设置 `VIRGO_REQUIRE_SANDBOX_TESTS=1`，将后端不可用视为失败，而不是能力跳过。仅通过模拟失败场景不能证明 OS 隔离有效；原生报告与完整跨平台对比报告是分别需要读取的验证结果。
