# 先规划，再执行变更

[文档首页](../README.md) · [English](../../en/guides/planning.md)

Plan 是可选的任务插件：提供调查与规划指令，维护一份带版本的 Markdown
方案，并让用户选择具体版本开始实施。它复用现有 Runtime 和 Agent Loop。

Plan 不切换权限预设，不隐藏普通工具，也不强制只读。提示词要求模型调查和
提出方案；实际工具能做什么由当前权限预设 决定。需要阻止项目写入时，独立
选择 Read-Only。可写权限本身不会把规划任务变成实施请求。

## 开始与修订计划

`coding` 预设启用 `plan`。在最小预设中可显式启用：

```json
{"profile": "minimal", "plugins": {"plan": {"enabled": true}}}
```

可以直接启动任务，也可以先选择 Plan 再发消息：

```text
/plan 调查配置加载流程，规划一个可选的超时设置。
/plan
调查配置加载流程，提出可选超时设置的实施方案。
/plan show
```

不带参数的 `/plan` 选择规划指令，并在已有方案时显示它。
`/plan off` 退出规划任务，不执行方案、不改变权限。`/permissions` 用于选择
权限配置，不再用于切换规划任务。

Plan 指令要求模型先读取项目说明、相关代码、现有测试和行为。存在 `ask_user`
时，仅对调查无法解决、且实质影响范围、方案、行为或验收的决策提问。未回答
的问题保留为待定事项或明确假设。

主 Runtime 通过 `propose_plan` 发布完整 Markdown，包含标题、目标、修改范围、
关键决策、实施步骤、验收条件与已知约束。它保存对话元数据，不创建项目文件，
也不授权实施。可以继续发消息要求修订，再用 `/plan show` 检查新版本。

每种任务都向模型提供正常的主工具集合，包括 `propose_plan`、文件工具、所选
Shell 和已启用插件的工具。执行权限检查仍然生效。显式只读的子 Runtime 也保留
正常工具定义，其权限上限在执行时实施。

## 编辑并执行选定版本

启用 Plan 插件后，Ctrl+G 打开计划编辑器。保存会替换完整 Markdown 并生成新
版本。未保存的修改不能执行；过期编辑窗口不能覆盖或执行更新后的方案。关闭
窗口会丢弃尚未保存的编辑。

对应命令：

```text
/plan edit
/plan edit <plan-id>:<revision>
<完整替换 Markdown>
/plan execute <plan-id>:<revision>
```

条件编辑应将版本、换行与完整正文作为一条命令提交；交互编辑也会检查打开时
的版本。执行要求精确匹配当前 token，缺失、过期或来自其他对话的 token 均被
拒绝。

用户执行命令为一次运行选择该版本，将任务指令切回 Default，并启动既有
Runtime。选定 Markdown 在当前请求上下文中只出现一次。权限预设 和审批策略
保持不变；需要的操作超出权限时，走统一的失败诊断和权限申请流程。

来源对话正在运行、或有排队／运行中的子任务时，编辑和执行会被拒绝，不排队
保存一次可能过期的版本选择。其他对话的工作不阻塞空闲来源。版本选择、状态
发布和运行准入共用既有会话锁；状态观察者不能重入这些操作。

## 方案、清单与权限

| 概念 | 含义 |
| --- | --- |
| Plan 任务 | 调查与方案指令，不额外收紧权限 |
| ProposedPlan | 一份 Markdown 正文及 `plan_id`、`revision` |
| Todo | 既有实施清单；发布方案不会自动创建或替换它 |
| 权限预设 | 在执行时实施只读、工作空间范围与联网设置 |
| 显式只读子任务 | 为委派任务设置的权限上限，与 Plan 无关 |

Plan 提示词要求避免用 Todo 代替方案，但启用 Todo 插件时仍提供 `todo_write`。
提示词表达任务目标，无法保证具有写权限的模型绝不发起写操作。

可选的 `git_read` 提供有界的本地 log/show/commit 比较，不启动仓库 helper 或隐式
联网。普通 Shell 工具同样可用，并受当前权限预设 约束。独立 Code Review
始终使用审查指令，即使从 Plan 对话中启动。

## 历史与请求边界

Plan 状态属于来源主 Runtime。切换对话不会让旧 Runtime 或子任务借用当前
可见对话的方案。恢复历史会恢复方案与 Plan 状态，不恢复正在执行的选择；历史
执行记录不会排队新运行，也不会恢复授权。

`plan` 和 `--plan` 是启动输入。显式启动覆盖在初始选定
对话运行首条消息前应用，包括 resume 选择器；它不会重写后续新对话的用户
默认值。有活动工作的保留来源会拒绝覆盖。

插件使用现有 SessionStore 的 `work_mode`、`proposed_plan` 和 `plan_execution`
记录。保存失败会阻止执行。请求级指令在每次模型请求和压缩上下文构建时重新
应用，保证工具循环、压缩和恢复后仍保留任务目标。未为当前运行显式选定的
方案始终标为提案。

关闭 `plugins.plan.enabled` 会移除其命令、方案工具和请求指令。Core 运行不
依赖 Plan 服务，不需要另一套任务循环。
