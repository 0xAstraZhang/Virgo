# 故障排查与恢复

[文档首页](../README.md) · [English](../../en/guides/troubleshooting.md)

## 从可见故障开始

| 现象 | 检查方向 |
| --- | --- |
| 全屏启动失败 | 使用交互终端和受支持的 `TERM`，或改用 `--ui plain` |
| 模型列表为空 | 等待启动刷新完成后重开 `/model`，检查 `/login`，或直接 `/model provider/id` |
| 更换服务地址后认证失败 | 为新协议／地址重新登录，保存的凭据与连接绑定 |
| 配置的 Shell 不可用 | 用 `/shell` 选择或指定受支持的可执行文件；Virgo 不会静默替换语言 |
| 保存历史失败后暂停 | 保持当前进程运行，解决文件系统问题，在切换或退出前查看诊断 |

`/diagnostics` 显示数据库位置和跨实例的最近十条错误，重启后也可查询。使用输出中的 `/diagnostics --before <cursor>` 查看更早的记录。`/diagnostics <error-id>` 根据完整 ID 或唯一前缀显示完整 JSON，完整 ID 匹配优先。这些命令不会改变模型历史或授予模型访问权。

首次写入时创建 `~/.virgo/logs/diagnostics.sqlite3`，或 `$VIRGO_HOME/logs/diagnostics.sqlite3`。SQLite 事务和唯一错误 ID 确保多个进程重复报告同一错误时只保留一条记录。`/new` 沿用数据库，各记录保留原始会话上下文。`--no-session` 仍会生成诊断日志。

所选权限预设拒绝 Shell 命令时，工具结果会指出第一个未获允许的命令、参数或 Shell 结构。这是权限拒绝，而非 Shell 临时故障，不应通过改写命令重复尝试相同操作。需要调查时使用文件读取工具或已识别的只读命令；需要修改时请求可写的运行环境。命令分类器采用保守策略，不构成操作系统级沙箱。

## 阅读诊断

| 字段 | 含义 |
| --- | --- |
| `error_id` | 跨边界传递时复用的稳定错误标识 |
| `phase`、`code`、`kind` | 发生阶段、机器可读分类，以及重试／溢出／致命／阻止类别 |
| `exception_type`、`cause_chain`、`traceback` | 实际异常、采集的原因链和堆栈位置 |
| `context` | 白名单关联元数据：会话、Runtime、Agent、工具调用、模型调用、尝试次数、耗时和 HTTP 信息 |
| `log_path`、`logging_error` | 记录保存位置，或日志失败原因 |

模型错误先看实际 API、HTTP 状态、request ID 和已有的重试信息；本地错误先看阶段、异常和原因链。后续重试成功不会删除之前的失败。异常消息是证据，不代表已经确认唯一根因。

错误没有条数上限，也不会因轮换被删除。SQLite 使用有界页缓存和 WAL 日志；Virgo 运行时，数据库及其 WAL 附属文件需要一起保留。平台支持时，新文件和目录使用受限权限。写入失败或一秒内无法获得写锁时，保留原始错误、标记保存失败并尝试向 stderr 输出脱敏记录。进程内应急缓存最多保留 100 条未保存错误；存储不可用时无法保证持久保留。`/diagnostics` 会将未保存记录纳入分页列表，数据库不可读时仍可显示这些记录。应急记录游标仅对当前进程有效；对应记录保存成功或离开缓存后，请重新运行 `/diagnostics`。

历史查询命令增量导入已有的 `harness-*.jsonl` 及其编号轮换文件，原文件保持不变。完整有效行按错误 ID 去重；格式错误或超大行会报告导入提示，末尾未完成的一行在后续查询时重试。导入进度分批提交，并检查已打开文件的当前大小，避免并发追加使已完成的进度归零。新错误写入和模型查询不会触发旧日志导入。

诊断不会主动收集 frame locals、源代码行、完整请求正文、headers、系统提示或对话消息，凭据和敏感元数据会脱敏。但应用错误消息和服务 stderr 仍可能含有业务文本，分享前应检查。此规则不改变会话历史和完整工具输出文件原有的存储约定。

## 模型可查看的证据

失败工具结果可追加最多 2 KiB 的诊断摘要，原有结果内容和 ID 保留。若当前 Runtime 暴露了该工具，模型可以通过 `diagnostic_get(error_id, section, cursor)` 按需取证。

| 栏目 | 证据 |
| --- | --- |
| `summary` | 白名单字段和关联上下文 |
| `causes` | 已采集异常链及有界位置 |
| `trace` | 已采集堆栈文本 |
| `stderr` | 连接失败时已收集、有界且脱敏的 MCP 服务 stderr |
| `attempts` | 同一逻辑调用及用途下，仍被保留且获授权的失败 |
| `related` | 已明确传播的关联诊断 |

查询使用完整 ID，不接受任意路径或 ID 前缀。权限属于调用 Runtime，共享记账存储或在界面选中其他对话不会授予访问权。证据和授权 ID 均无条数上限。过滤后的快照及通知状态存入各 Runtime 独立的私有临时 SQLite 数据库，位置在受保护的日志目录内。Runtime 清理时删除临时存储；重新打开保存的会话时，仅从其自身历史分支恢复授权，不会从全局日志补取模型证据。单条过滤证据仍最多 64 KiB。未知或未授权 ID 返回 `not_found`，未采集的栏目或读取失败返回 `unavailable`。完整 JSON 响应每页最多 8 KiB，游标绑定 Runtime、错误、栏目和证据集合版本；证据变化后需重新分页。重试证据按调用索引分页读取，无需一次加载全部失败记录。

`plugins.diagnostic_get.enabled=false` 关闭面向模型的证据读取工具；Core 日志、错误 ID、有界结果摘要与恢复证据保留，`/diagnostics` 也仍可使用。诊断在正常模型请求边界追加；收集证据不会自行启动模型轮次，也不会改写旧消息。

## 执行失败不等于没有副作用

`details.execution` 记录工具是否已经启动，以及返回成功、错误或未知结果。工具成功后的结果钩子失败，不会撤销原操作。超时命令、失败的子 Agent 或丢失的远程响应，都可能已经修改文件或外部状态。重复操作前应先核对结果。

Provider 重试仍由 Runtime 的现有策略统一控制。有效 `Retry-After` 是最短等待，`retry.maxWaitSeconds` 限制累计等待。已经启动服务端原生网页操作的请求，不会作为“不支持能力”的回退而自动重放。

## MCP 扩展

MCP 不是内置能力，安装和配置见[MCP 扩展](../../../extensions/README.zh-CN.md)。`mcp_status` 只读取扩展的本地连接状态，不联系服务。`/mcp` 列出已配置服务器；`/mcp reconnect` 重新加载 `mcp.json` 和 `mcpServers` 配置项。

重新加载会先连接所有已配置服务器，再统一发布。任一候选失败时保留原有连接和工具并报告失败。成功后在下一个模型请求边界发布新工具集；连接被替代后，旧工具句柄会保守失败。重连从不重放失败调用。取消的调用会向服务器发送 `notifications/cancelled`，但已经丢失的响应仍使业务结果保持未知。

连接失败会附带来自服务器的有界、脱敏 stderr 尾部，并记录为诊断。

## 会话保存失败

写入失败后，会话存储保留逻辑上的内存记录，并通过独立日志报告原始原因。调度暂停，同时通知所属 Runtime，避免继续执行却不断积累未保存历史。切换界面不会修复失败存储，诊断通知也不能清除取消或保存失败状态。在恢复需要的未保存信息前，应避免关闭进程。

实现：[诊断](../../../src/virgo/diagnostics.py)、[日志存储](../../../src/virgo/harness/diagnostics.py)、[Runtime 证据](../../../src/virgo/harness/diagnostic_access.py)、[恢复](../../../src/virgo/harness/recovery.py)、[MCP 扩展](../../../extensions/mcp.py)。

## 插件配置与升级

未知插件 ID 或非法配置会在启动时报错。可选插件初始化失败会说明插件名称和降级状态，并回滚部分注册；禁用插件不会启动对应服务。项目 Python 扩展需要来自项目之外的信任，审查后才使用 `--trust-project-extensions`。

旧定时任务按设计不再执行。Schedule、Workflow、Team、Tasks、Memory 和 Goal 已移除，原文件保留供人工检查；见[迁移](migrating-to-core-plugins.md)，无需通过旧功能开关重新激活。
